Incident benchmarks for AI agents usually count an episode as solved once the system looks healthy, which cannot
separate a repair from a restart or configuration tweak that merely suppressed symptoms. Our three-round external oracle
checks the service the agent left, replays the incident-inducing load on it, and replays it again on a system rebuilt
from the agent's code and configuration; a fix passing all three rounds is durable. Validated on 37 scenarios (111/111
runs as expected), it is applied to 12 injected faults in a Node.js order service under five arms (do nothing, restart,
and a large-language-model agent that may only mitigate, must fix the code, or decides freely), with \numairunsHaiku{}
agent runs of Claude Haiku~5.5 and \numairunsGemini{} of Gemini~3.8~Flash (nearly half cut off at 300~s). A liveness
probe credits \numliveIdlePctHaiku\% of the runs where nothing was done; against each fault's own criterion,
\nummitTempShareHaiku\% and \nummitTempShareGemini\% of the mitigation-only agent's successes are temporary (23--49\%
and 23--39\% leaving out any one fault). Durable is not yet repaired: on code faults, every durable fix of the
mitigation-only agent was a configuration workaround, such as a one-connection database pool that avoids a deadlock. On
eight SREGym problems, the extra rounds reject hand-written workarounds that SREGym's oracle accepts in three of four
testable problems, yet none of the 36 agent fixes it accepted (Claude Haiku and Sonnet~5.5) was temporary. Isolating the
grader from the agents took four iterations. The pre-registration log, harness, and run records are public.
