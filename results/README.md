# results

Every order-service set is a directory with `pilot_results.jsonl` (one line per run: fault, arm, the three rounds, verdict,
flags) and `run_evidence.jsonl` (evidence: ticket, commands the agent ran, diff, measurements of each round, the agent's
closing message). The `harness` field of each run is the commit of the working repository that ran it; the rules and every
change are in `../PRE-REGISTRATION.md`. A set's report is `<set>/analysis.md`, generated by
`remediation-oracle/analysis.py` (needs `../requirements.txt`). SREGym sets (`sregym-*`) hold `runs.jsonl` (one line per
run with the round results and the `gate.py` hash), `infra.jsonl` (runs dropped as infrastructure errors and rerun),
`peek_review.csv` (peek decisions read by hand), and `logs/`.

The two v3 sets ran under different infrastructure (pre-registration log, 2026-11-06 and 2026-11-07). For Gemini the

from the full command output (`cross_model.py --write-peek-success v3-haiku55-main`), which the public copy removes, and
`cross_model.py` reads it instead of recomputing.

## Pooled analysis, comparisons, and figures

`cross_model.md` and `figures/` (`outcomes_by_arm`, `real_fix_by_fault`, `code_fault_mechanism`, as PDF and PNG) are
generated by `remediation-oracle/cross_model.py` from the two v3 sets. Sections 1 to 4 put the sets side by side with the
same computations as `analysis.py`; section 5 holds exploratory analyses outside the pre-registered plan (timeouts,
pass^k, sensitivity to the `peek` definition, repair mechanism, cost, leave one fault out). `wp4-compare.txt` is the WP4'
comparison from `remediation-oracle/compare_wp4.py`, and `wp4-pilot-tokens.json` holds the token counts of its six pilot
runs. `compare_v1_v2.md` and `compare_v1_v3.md` compare the leaky v1 harness with later sets. The paper's LaTeX tables are
generated from these sets by `paper/make_tables.py`.

apart). The directory name dates from v2; each batch's gate filters by time: Mac mini from 2026-10-22T16:47 (111/111),
MacBook from 2026-11-06T23:10:04 (111/111), and again before E1 (2026-11-12) and WP4' (2026-11-15), 111/111 each.
`sregym-gate/` holds the SREGym gate logs: `g1/` (12 problems, once each), `g2-full-dev/` (development run, full profile),
and `g2-svelte/` (the G2 gate, 8 problems x 3, checked with `sregym-oracle/check_g2.py`).

## What the public copy changes

This copy was produced from the working repository by a scrubbing script, which does three things:

- it replaces home directory paths, e-mail addresses, host names, and the names of the local model proxy and its providers
  with neutral placeholders (`/Users/user`, `author@example.com`, `host-a`, `host-b`, `model-proxy`);
- it removes the captured output of agent commands from `run_evidence*.jsonl` and `transcripts/` (keys `output`,
  `output_head`, `aggregated_output`), because agents listed directories of the author's home; the commands, diffs,
  verdicts, flags, and closing messages stay, which is enough for `analysis.py` and `cross_model.py`. `rescore_peek.py`
  needs the output and therefore runs only on the original data;
- it leaves out the operational logs (`logs/`), the agent logs of the stopped Google arm of WP2, and the RQ3 keys.

Editors and reviewers can obtain the withheld files from the author.
